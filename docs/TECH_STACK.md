# Tech Stack

## Frontend

- **Framework:** Flutter (Dart), current stable channel — why: single codebase for iOS + Android, strong built-in RTL support (needed for Arabic UI), good offline-first story.
- **State management / DI:** Riverpod (`flutter_riverpod` + `riverpod_annotation`/`riverpod_generator`) — standard, testable state management for Flutter; codegen keeps the many repository/service providers this app needs (content, progress, speech) low-boilerplate. **One verified exception:** `riverpod_generator` (as resolved, v4.0.8 against riverpod 3.4.2) throws `InvalidTypeException` when asked to generate a provider whose return type is a Drift-generated `DataClass` (e.g. `Learner`, `UnitProgressData`) directly — `currentLearnerProvider` and `allUnitProgressProvider` are therefore hand-written `FutureProvider`s instead of `@riverpod`-annotated functions; every other provider in the app uses codegen normally. Riverpod 3.x also renamed `AsyncValue.valueOrNull` to `AsyncValue.value`.
- **Navigation:** `go_router` — official Flutter routing package. `StatefulShellRoute.indexedStack` is the right primitive for the 5-tab bottom nav (Home/Learn/Review/Tests/Settings) with independent per-tab navigation stacks, plus typed/centralised routes and a root `redirect` that gates all routes on curriculum-content-load status (loading/unsupported/ready) — see [ARCHITECTURE.md](ARCHITECTURE.md).
- **Alternatives considered:** React Native/Expo — would let logic share with a JS/TS backend, but the app has no custom backend (see below), so that advantage doesn't apply here; Flutter's RTL support tipped the decision.

## Backend

- **Firebase only, and only for optional accounts and progress sync** ([ADR 0010](adr/0010-optional-accounts-and-progress-sync.md); [ADR 0001](adr/0001-offline-first-firebase-only-backend.md)'s "Firebase as the only backend" direction). **Firebase Authentication** (email/password, Google) and **Cloud Firestore** (each account's progress under `users/{uid}`). No Cloud Storage, no Cloud Functions. The app still compiles and runs with no Firebase configuration: `main.dart` catches the placeholder `firebase_options.dart` and the app is local-only.
- Packages: `firebase_core`, `firebase_auth`, `cloud_firestore`, `google_sign_in` (7.x: on Android it takes the web client id the `google-services` Gradle plugin generates from `google-services.json`). Only `features/account/data/` and `features/sync/data/` import them.
- **Firestore's offline persistence is switched off** (`Settings(persistenceEnabled: false)`): Drift is already the offline store and the source of truth; a second cache would make a queued write look uploaded when it wasn't.
- **Alternatives considered:** Python/FastAPI, Node.js/TypeScript — rejected; a maintained server isn't needed for a solo, offline-first app, and adds operational burden with no corresponding benefit at this stage.

## Database

- **Local (on-device):** Drift (SQLite-based) — stores learner progress only (enrolments, attempts, mastery evidence, review state — see [DATA_MODEL.md](DATA_MODEL.md)). It does **not** store curriculum content: each released level's bundle (A1, A2) is a bundled read-only asset, parsed and indexed in memory (see [ARCHITECTURE.md](ARCHITECTURE.md)'s `lib/content/` module), and Drift only ever references the bundle's stable string IDs. Explicit, stepwise schema migrations (now at v6). Native SQLite access is via `drift_flutter` (the `driftDatabase()` helper, which handles per-platform database-directory setup) + `sqlite3` — **not** the older `sqlite3_flutter_libs`, which is now end-of-life (a no-op package kept only so old apps don't break); `sqlite3` 3.x bundles its native library automatically via Dart's native-assets/hooks mechanism, verified working in `flutter test` on Windows during Phase 3 scaffolding.
- **Cloud (sync):** Cloud Firestore — one document per progress record, merged per record ([API_CONTRACT.md](API_CONTRACT.md)). A copy, never read by a screen. The local-to-cloud queue is a Drift table fed by SQLite triggers (`sync_outbox`).
- **Device/UI preferences:** `shared_preferences` for small, non-critical settings only (theme mode, colour theme, interface language, text scale, the voice-speed preference (and a pitch value no longer shown — bundled clips have no pitch to change), "seen onboarding" flag) — never for progress data, so a "reset progress" action in Settings can never accidentally also reset the learner's language/theme.
- **Alternatives considered:** Isar, Hive — considered for local storage; Drift chosen for its relational/SQL querying, which fits structured curriculum-reference and mastery-evidence data (e.g. one indexed join per Can-Do objective across skill groups) better than a pure key-value/NoSQL local store.

## Content models

- **Immutable content models:** `freezed` + `json_serializable` (+ `build_runner`), scoped specifically to `lib/content/models/` — the curriculum bundle's nested, sealed-union shapes (9 activity types, 8 media-specification types) benefit from freezed's union support and reliable `fromJson`/`toJson`. **Not** used for Drift row classes, which already generate their own immutable data classes — avoiding redundant/colliding codegen.
- **Why not hand-written models throughout:** the bundle graph is large (~1,200 leaf records across units/lessons/activities/grammar/lexicon/chunks/media) and schema-versioned; generated `fromJson` plus a `schemaVersion` guard is more reliable than hand-rolled parsing for something this size.

## Localisation

- **Flutter's ARB-based l10n** (`flutter_localizations` + generated `AppLocalizations`) — app-chrome strings only (buttons, navigation, system messages). Curriculum content (lesson text, grammar/vocabulary explanations) is bilingual *within the bundle itself* (`en`/`ar` fields per record), never routed through ARB files.

## Speech

- **Bundled speech audio (primary):** every string the app speaks — conversation lines, listening transcripts, partner turns, model texts, key phrases, headwords, examples, grammar forms — ships as a pre-generated clip under `assets/audio/en/<LEVEL>/` with a per-level `manifest.json` ([ADR 0008](adr/0008-bundled-pre-generated-speech-audio.md), schema in [DATA_MODEL.md](DATA_MODEL.md)). Generated on the authoring machine by `tool/audio/generate_audio.py` with **Kokoro-82M v1.0** (Apache 2.0, via `kokoro-onnx`), one voice per dialogue character from `tool/audio/cast.json`, encoded to mono AAC at 32 kbps with the ffmpeg that `imageio-ffmpeg` bundles. Played by `audioplayers` (already a dependency) through `BundledAudioTextToSpeechService`; "Slower" is a playback rate. Why not an online engine or a better built-in voice: the ADR. Roughly 50 MB for A1 and A2 together; the level gate caps each level at 60 MB.
- **On-device TTS (fallback only):** `flutter_tts` — wraps iOS `AVSpeechSynthesizer` / Android `TextToSpeech`. Speaks only text that has no bundled clip, which for shipped content is nothing; it stays so a missing or broken manifest degrades to the old behaviour rather than silence.
- **On-device STT:** `speech_to_text` (already decided, [ADR 0003](adr/0003-on-device-speech-writing-assessment-for-mvp.md)) — exposes per-locale on-device availability, a listen/result stream, offline-vs-online status.
- **Microphone permission:** `permission_handler` — unifies iOS Info.plist-driven and Android runtime-permission flows behind one call; needed to check/request mic permission only when a speaking task is deliberately started, and to report status plainly in Settings.
- Phase 8 verified all three directly against the installed package source (not memory) before writing `DeviceTextToSpeechService`/`DeviceSpeechRecognitionService`/`DeviceSpeechCapabilityService` — flutter_tts 4.2.5, speech_to_text 7.4.0, permission_handler 13.0.1, all actively maintained, no deprecation notices. **Not yet verified against a real Android/iOS device or emulator** — none is available in this dev environment (see [TESTING.md](TESTING.md)); automated tests instead fake the service interfaces (`FakeTextToSpeechService`/`FakeSpeechCapabilityService`/`FakeSpeechRecognitionService`) to verify capability-detection, permission, and fallback *logic*.
- **Platform permission declarations** (Phase 10, verified against `speech_to_text`'s and `permission_handler`'s own READMEs, not memory): Android needs `android.permission.RECORD_AUDIO` plus a `<queries>` entry for `android.speech.RecognitionService` (required on API 30+ package-visibility rules so the plugin can find the on-device recognizer at all) — both were missing from `android/app/src/main/AndroidManifest.xml` until Phase 10, a real gap that would have silently kept real speech recognition unreachable on every Android device. iOS needs `NSMicrophoneUsageDescription` and `NSSpeechRecognitionUsageDescription` in `ios/Runner/Info.plist` — both were missing until Phase 10, which on iOS is worse than "silently unreachable": the OS terminates an app that requests a permission with no matching usage-description string, so the first speaking-task attempt on a real iPhone would have crashed outright. Neither gap was caught earlier since no real device/emulator has been available in this dev environment to exercise the actual permission-request path. The iOS strings are English-only for now — proper Arabic localization needs an `ios/Runner/*.lproj/InfoPlist.strings` setup wired into the Xcode project, which this environment has no Xcode install to verify actually gets bundled correctly; deferred rather than risking an unverified half-wired iOS project-file change.

## Utilities

- **`uuid`** — generates the app-level stable identity of every progress record's `uuid` column, which is also its document id in the account's cloud copy; the account itself is identified by its Firebase UID (`learners.firebase_uid`).
- **`path_provider`** — resolves the app documents directory for the local SQLite file.
- **`collection`** (Dart team) — grouping/indexing utilities used building the in-memory `CourseContentIndex`.
- **`audioplayers`** — plays the short correct/incorrect feedback sound effects (two generated `.wav` assets under `assets/sounds/`) after a live activity submission. Chosen over `flutter_tts` (speech only, not arbitrary short audio files) and over Flutter's own `SystemSound` (only exposes a couple of fixed OS click sounds, not custom audio). `SoundEffectsService`/`playFeedbackSoundSafely` (`lib/features/activity_engine/domain/sound_effects_service.dart`) wrap it behind the same fire-and-forget, error-swallowing pattern as `PendingRefinementDrainer.triggerDrain()` — a missing platform audio engine must never crash or block the activity flow.

## Infrastructure / hosting

- One Firebase project (Auth + Firestore), set up per [FIREBASE_SETUP.md](FIREBASE_SETUP.md); rules deployed with `firebase deploy --only firestore:rules,firestore:indexes`. No server of our own. A build without the project's configuration still runs, local-only.

A cloud voice (Google Chirp 3 HD) is the documented upgrade path behind the same tool boundary |

| LLM API (e.g. Claude) | Content generation — used in the offline dev-time authoring pipeline only (`reference/a1-modular-course/`), not called by the shipped app | You review/edit AI output before it's built into the runtime bundle; never bundled as a client-side key — see [SECURITY.md](SECURITY.md) |
| Free public LanguageTool API (`api.languagetool.org`) | Grammar/spelling-quality pass for open-ended answers on rubrics marked `onlineRefinement`, once the device is online — 59 rubrics across both released levels (23 in A1's units, 36 in A2's), every one a `write` task, none in either level's capstones. It carries **typed text only**: a `speak` rubric marked this way would queue a recognised speech transcript, which [ADR 0005](adr/0005-narrow-network-exception-for-open-ended-grading.md) excludes by name, and `test/content/online_refinement_boundary_test.dart` fails on one in any shipped bundle. See [SECURITY.md](SECURITY.md) | Free, no API key, no cost; rule-based, not AI/LLM; a bounded quality upgrade, never required — see [ADR 0005](adr/0005-narrow-network-exception-for-open-ended-grading.md) |
| Firebase Authentication | Optional sign-in (email/password, Google) | Free tier covers email/password and Google sign-in; see [SECURITY.md](SECURITY.md) |
| Cloud Firestore | A signed-in learner's progress, copied between their devices | Free tier (50k reads / 20k writes a day); downloads are incremental (cursor per collection), so a launch never re-reads everything |
| Firebase Emulator Suite (dev-only, `tool/firestore_rules_test/`) | Tests `firestore.rules` | Needs Java 11+; never used by the app |

Not used: Firebase Cloud Storage, Cloud Functions, Analytics, Crashlytics.

**Explicitly not adopted for v1:** any analytics or crash-reporting SDK, any local-backup export/import mechanism — both decided out of scope this session; see [ROADMAP.md](ROADMAP.md).

## Explicitly rejected

| Option | Reason rejected |
|---|---|
| Custom backend server (Python/FastAPI or Node.js) | Not needed for a solo, offline-first app; Firebase covers the actual requirements (auth, sync) without server upkeep. |
| Firestore offline persistence as the app's progress store | Drift already answers every progress query (mastery is SQL); see [ADR 0010](adr/0010-optional-accounts-and-progress-sync.md). |
| Cloud-based AI grading for speaking/writing at runtime | Conflicts with "fully offline" requirement for MVP; deferred to post-MVP roadmap (see [ROADMAP.md](ROADMAP.md)) once a serverless AI-grading path (e.g. Firebase Cloud Functions) is worth the added complexity. Does **not** cover the narrow, rule-based (non-AI) LanguageTool grammar check added for open-ended rubrics — see [ADR 0005](adr/0005-narrow-network-exception-for-open-ended-grading.md), a bounded exception, not a reversal of this rejection. |
| React Native/Expo | Flutter's RTL support and single-codebase story fit better; no backend exists to share TypeScript types with. |
| Bundling artwork/SVG assets for the curriculum's 7 structured scene-media types (`peopleCard`, `personCard`, `peopleMap`, `homePlan`, `objectScene`, `distanceScene`, `apartmentPlan`) | These are structured scene *descriptions* in the bundle, not image files — no artwork exists to bundle. Rendered instead as small in-app diagrams built from the data (see [ARCHITECTURE.md](ARCHITECTURE.md)); `flutter_svg` and similar packages are therefore not needed. |
| Analytics / crash-reporting SDK in v1 | Decided out of scope this session — keeps zero required network calls/third-party telemetry while the app is fully local; see [ROADMAP.md](ROADMAP.md). |
