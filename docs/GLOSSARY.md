> **What this file is:** The one definition per domain term, so "Order" doesn't mean one thing in the API and another in the UI copy.
> **How to use it:** Before introducing a new domain noun (entity, status, role), check here first. If it's not here, add it the moment you name it in code.

# Glossary

| Term | Definition | Notes / not to be confused with |
|---|---|---|
| CEFR | Common European Framework of Reference for Languages — the 6-level scale (A1–C2) the app's curriculum is structured around. | |
| Agreement version | The version of the privacy policy and terms a learner accepted on the first-run screen (`kAgreementVersion`, stored as `legal.acceptedAgreementVersion`). Raised only when the documents change in a way that matters; then the agreement is shown again. | Not the app version — most releases change neither document. |
| App guide | The coach-mark tour over Home and the tab bar that teaches where things are. Starts once on first launch; Settings → App guide reopens it. | Not onboarding slides, and not a lesson. |
| Delete account | Permanently deleting a learner's account, its cloud copy of their progress, and that account's learner on the device, from Settings. Guest progress on the device is kept. | Not Reset progress (keeps the account) and not Sign out (keeps everything). |
| Level | A single CEFR level (e.g. A1), identified by the curriculum bundle's `course.id` (e.g. `"EN-A1-V2"`). | Not to be confused with "level" as a loose skill descriptor — it always refers to a CEFR level entity. |
| Current level | The level a learner is working in: their most recently selected enrolment (`course_enrolments.lastSelectedAt`), the base level by default. Learn, Home, Tests, Words & phrases and Grammar all follow it. Two things deliberately don't: Review spans every level the learner has reached, and the placement test covers every released level — neither belongs to one level (see [ADR 0006](adr/0006-multiple-levels.md) and [ARCHITECTURE.md](ARCHITECTURE.md)). | Not the level a screen happens to be *showing* — browsing a level (see Level lock) never changes it. See `currentLevelIdFor` in `lib/features/progress/domain/level_access.dart`. |
| Level complete | Every unit that counts towards a level (`countsTowardLevelMastery` — a starter unit like `A1-U0` doesn't) is mastered. It is what opens the next level without an explicit unlock. | Not "passed the Final Assessment": that is a separate result and does not currently mark a level complete. See `levelComplete`. |
| Level lock | Whether a level is open for a learner right now (`LevelAccess`), one of three states: **open**; **locked behind its prerequisite but openable anyway** — released, just not yet reached, and the learner can take the placement test or open it regardless; **not released yet** — the app hasn't shipped its lessons, so only browsing is offered. Always explains itself and offers a way forward, never a dead end. | Not a hard gate — see [PRODUCT.md](PRODUCT.md) flow 5 and [UX_PRINCIPLES.md](UX_PRINCIPLES.md). |
| Earlier-level reference | A lesson's grammar, word or phrase id that belongs to an earlier level (an A2 lesson listing `A1.G.BE.I_AM`) — the earlier record is reviewed, never copied. Shown to learners as "From A1". Declared by the catalogue's `prerequisiteLevelId`. | **Nothing uses this today.** A2 lessons list no A1 id (0 across all 84), by the product owner's decision that a learner in A2 is assumed to know A1 — the resolution path, the loading of A1 alongside A2 and the "From A1" badge are kept unused for grammar and for B1. See [ADR 0006](adr/0006-multiple-levels.md). Not a new record: the id, its review schedule and its page stay the earlier level's. |
| ~~Block~~ (superseded) | Originally: a thematic sub-section of a Level, grouping several Units. | The real curriculum data has **no Block entity** — A1 is 13 flat Units (`A1-U0`…`A1-U12`) and A2 is 12 (`A2-U1`…`A2-U12`), with no grouping field. [PRODUCT.md](PRODUCT.md)'s "4 thematic blocks" language is descriptive framing of the unit sequence only, not a modeled or gated data entity. |
| Unit | A top-level curriculum section (e.g. `A1-U1`, "Hello, I'm…"). Contains several Lessons. Carries its own `mastery` policy (`requiredObjectives`, `requiredSkillGroups`). | Was previously described as "the smallest gated progression step" — no longer accurate; see [ADR 0004](adr/0004-local-only-v1-no-firebase-backend.md) and [PRODUCT.md](PRODUCT.md) flow 5 (recommended, not hard-gated). |
| Lesson | A single teaching session within a Unit (e.g. `A1-U1-L1`, "My Name"). Contains an optional `encounter` dialogue and several Activities. | New term vs. the original glossary — sits between Unit and Activity; did not exist in the original Unit→Exercise model. |
| Activity | One typed exercise within a Lesson, replaces the original "Exercise" term. Typed by `type` (one of `audioChoice`, `textChoice`, `match`, `order`, `gap`, `form`, `speak`, `write`, `dialogue`), `mode` (`encounter`/`practice`/`mastery`), and one or more `skill` values. | ~~Exercise~~ is superseded by this term — "Activity" matches the curriculum bundle's own vocabulary. |
| Mode | Whether an Activity is first-exposure (`encounter`), unscored rehearsal (`practice`), or mastery-evidence-bearing (`mastery`). `practice` never counts as mastery evidence. Learners see a mode as the lesson player's **phase**: `encounter` = "Warm-up" / "إحماء", `practice` = "Practice" / "تدريب", `mastery` = "Use it" / "تطبيق" — UI labels only; code and data keep the mode names. | New term — did not exist in the original model, which conflated all Exercise attempts as equally gating. |
| Skill | One of the 6 competencies tracked per the curriculum bundle's `domain.SKILLS`: `listening`, `reading`, `writing`, `spokenInteraction`, `spokenProduction`, `mediation`. | Supersedes the original 4-skill list — speaking is split into spoken *interaction* vs. *production*, and *mediation* (relaying/explaining information between languages) is a distinct tracked skill not previously named. Vocabulary/grammar remain cross-cutting content, not Skills themselves. |
| Can-Do objective | CEFR's standard way of describing what a learner can actually do, given a stable ID in the bundle's `domain.CAN_DO` map (e.g. `A1.U1.PRODUCTION.INTRODUCE_SELF`). Units declare `requiredObjectives`; Activities declare which objective(s) they provide evidence for. | Used at a finer grain than the original glossary implied — evidence is tracked per objective, not just per Unit. |
| Test mode | How the placement test and final assessment run: answers are saved but not marked while the test is running, and listening questions have no transcript. Results come at the end. | The final mission is not in test mode. |
| Weak spot | A lesson whose Can-Do objectives, in a unit the learner is working on, don't yet meet the mastery threshold — how the Review tab names weak objectives to learners (by lesson title, level, unit and skills), since the bundle has no learner-facing Can-Do text. Weak spots come from every level the learner has a unit in progress in, which is why each names its level. | Never show a raw Can-Do id to a learner, and never a unit number without its level. |
| Review session | The Review tab's run through every word and phrase due for spaced review — from **every level the learner has reached**, not just the one they are in: card by card, rated Again/Good/Easy. Updates the vocabulary memory schedule only. An item enters spaced review when the lesson that teaches it is finished (first due the next day), or when the learner rates it on its word or phrase page. | Not "practice" (quick practice, a short set of questions) and not mastery. Never level-scoped: an A2 learner's A1 words are what spaced review is for. |
| Practice set | What quick practice runs: up to three questions for one weak spot (from the lesson that teaches it) or one grammar form (from the lessons that use it), with a summary at the end. Saved as `practiceReview`, so it never counts towards mastery. | Not a lesson and not a review session. |
| Mastery evidence | A recorded result for one `(Can-Do objective, Skill, Mode)` combination, produced by a `mastery`-mode Activity attempt. A Can-Do is "mastered" per the bundle's `MASTERY_POLICY` (minimum score, minimum evidence count, no single compensating average across skill groups). | New term — replaces the original single-score "pass/fail" framing. See [DATA_MODEL.md](DATA_MODEL.md). |
| Grammar / Lexicon / Chunk (registries) | Three cross-referenced content registries in the curriculum bundle: `grammar` (one record per structure, e.g. `A1.G.BE.I_AM`), `lexicon` (one record per lexical *sense* — two words with identical spelling but different senses are distinct records), `chunks` (fixed functional phrases, e.g. `A1.CHUNK.GOOD_MORNING`). Each Lesson references the registry entries it introduces. | Not present in the original glossary at all — the original model had no vocabulary/grammar data shape. |
| Placement test | **Gateway Placement Test** — a short assessment that finds where a learner should start, across every *released* level. It classifies into one of four actionable outcomes (start with English Essentials, start a level from its beginning, start at a specific unit, or the top released level looks mastered) and never claims a level the app has no content for. Runs as a block pass with drill-down (below), so the unit it stops at is itself the recommendation. | The bundle itself contains no dedicated placement item pool — receptive (listening/reading) items are sampled from existing Unit `practice`-mode activities only; the one productive (write/speak) supporting item per attempt also draws from `mastery`-mode content where needed, since most units have no `practice`-mode productive activities at all (verified against the real bundle) — see [ARCHITECTURE.md](ARCHITECTURE.md). |
| Placement block | A run of consecutive units of one level that the placement test passes or fails as a group, on one item per unit — A1's U0-U3, U4-U6, U7-U9, U10-U12; A2's U1-U3, … Three units each, except a level with a starter unit, whose opening block absorbs it. | Not a curriculum entity: nothing in the bundle groups units (see ~~Block~~ above). It exists only inside the placement scan — `splitIntoPlacementBlocks`, `PlacementScoring.blockPassed`. |
| Drill-down | What the placement test does to a **failed** placement block: takes its units in order, asks up to three fresh items about each, and stops at the first that fails — that unit is the recommendation. A block whose units all pass on the second look is left behind and the scan carries on. | A failed block by itself recommends nothing; only a drill-down can name a starting unit, which is what keeps "never skip a whole unit on one answer" true. |
| Final Mission | One per level (`A1-FINAL-MISSION`, `A2-FINAL-MISSION` "Host a Visitor") — a scenario-based capstone activity set, separate from ordinary lesson training, required after completing the guided path. Six stages, twelve activities. | New term — did not exist in the original model. A2's exists in the bundle but has no route into it yet (see Current level). |
| Final Assessment | One per level (`A1-FINAL-ASSESSMENT`, `A2-FINAL-ASSESSMENT`) — a summative exit test with secured, unseen items (never drawn from training content), scored per skill with no single overall average hiding a failed essential skill. Both levels pass at 0.6 per skill, deliberately the same bar: both are keyword-marked by the same evaluator, so "finished A1" and "finished A2" have to mean the same thing. Unit mastery stays 0.75. | New term — did not exist in the original model. A2's exists in the bundle but has no route into it yet (see Current level). |
| Content gate | A Dart test over a shipped bundle that a level must pass before it may be marked `available` — one suite in `test/content/levels/`, run over every level in `kLevelGates` (`level_gate_config.dart`). Each gate runs over the level's finished-units list, which a unit joins in the batch that authors it, and the release rule refuses `available` unless that list is every unit in the bundle *and* both capstones pass. A level's genuine differences are declared exceptions — a value with a written reason, never a skip. | Not the authoring package's Node validators (see Content pipeline), which check the authoring sources, not the shipped file. Until 2026-09-22 A2 had forty-seven of these and A1 five; A1 is now held to the same suite. |
| Attempt | A Learner's recorded result for one Activity, one placement item, or one Final Mission/Assessment item. Insert-only — retrying/replaying an Activity appends a new Attempt rather than overwriting the previous one. | Broadened from the original "Exercise or Unit assessment" framing to cover placement/mission/assessment attempts too, each kept in its own isolated attempt history. |
| Learner | An app user — always a self-directed adult, native language Arabic, target language English for MVP. On the device, one `learners` row per owner of progress: the Guest, or an Account that has signed in here — each with a local UUID; an account's row also carries its Firebase UID (`firebaseUid`). | Not "student" (implies classroom/teacher, which is explicitly out of scope). Not "user" in code for the local row — `AuthUser` is the signed-in identity, `Learner` the progress owner. |
| Account | An optional Firebase Authentication identity (email/password, Google, or Apple on iPhone), keyed by its Firebase UID, that owns a copy of one learner's progress in Firestore and follows them across devices. See [ADR 0010](adr/0010-optional-accounts-and-progress-sync.md). | Never required for any learning feature. |
| Guest | The learner on a device when nobody is signed in: a `learners` row with no `firebaseUid`. At most one per device. Its progress stays on the device unless the learner chooses to add it to an Account on first sign-in. | Existing installs' progress became the Guest's at schema v6. |
| Sync | Copying a signed-in learner's progress between the device's Drift database and their Account's Firestore copy, in the background — upload the Outbox, download what changed elsewhere, merge each record by its collection's rule. Drift stays the source of truth. | Not "backup" (it merges between devices) and not a live connection (it runs on triggers: launch, local changes, reconnect, foreground, every 10 minutes, Sync now). |
| Outbox | `sync_outbox`: the queue of local rows changed since they were last uploaded, filled by SQLite triggers, emptied only when the cloud acknowledges an upload. | |
| Epoch | An Account's progress generation (`users/{uid}.epoch`). "Reset progress" while signed in starts a new one; every device then erases what it holds under the old one. | Only ever increases. |
| Native language / Target language | The learner's own language (Arabic, fixed for MVP) vs. the language being learned (English, fixed for MVP). | |
| ContentItem | The authoring-side record tracking a Unit/Lesson/Activity through the content review workflow (draft/approved/published), used only inside the separate curriculum-authoring package (`reference/a1-modular-course/`), never inside the shipped app. | Not visible to Learners — authoring-only concept; the shipped app only ever consumes the already-`published` bundle output (`dist/a1-course-bundle.json`). |
| Content pipeline | The dev-time (non-shipped) process of generating lesson content, running it through the curriculum package's own validators (`validate-a1.mjs`, `audit-quality.mjs`, `build-a1.mjs`), and reviewing it before it's copied into the app as a bundled asset. | Distinct from the app's runtime — the pipeline never runs on a learner's device, and in v1 there is no Firestore "publish" step, only a local asset copy (see [ADR 0004](adr/0004-local-only-v1-no-firebase-backend.md)). |
| Stale unit | A Unit the learner has progress in whose content moved under them: they have a recorded answer against an Activity that is no longer in the bundle, or the unit's required Can-Do objectives are not the ones it required when they worked on it. Stored as `unit_progress.isContentStale`, written by the content-version diff rather than by mastery aggregation, and surfaced on the Learn tab's unit row. | New term. Distinct from **Needs review**, which is about the learner's evidence decaying; a stale unit is about the *content* changing. Informs, never blocks. See [DATA_MODEL.md](DATA_MODEL.md). |
| Published id snapshot | The committed record of every unit, lesson, activity and Can-Do id a level has shipped, each activity's `mode` and `canDo` list, and the `contentVersion` they were recorded under (`test/content/published/<level>-published-ids.json`). What makes "ids are permanent after publication" a rule a test can check rather than a sentence. Updated with `dart run tool/update_published_ids.dart`, which merges and never regenerates. | New term. See [CONVENTIONS.md](CONVENTIONS.md) for the rules it enforces and why each one matters to a learner. |
| Content catalogue | The app-owned, level-agnostic table of which CEFR levels exist and their availability (`available` for A1 and A2, `comingSoon` for B1–C2), and, per level, the level it builds on (`prerequisiteLevelId`: A2 → A1). Distinct from any single level's curriculum bundle. | New term — needed once more than one level is modeled. The third state, `preview` (content loads and is browsable, lessons stay closed), has no level in it since A2's release — it is how the next level will ship while it is being written. |
| Clip | One pre-generated audio file for one spoken string in one voice, under `assets/audio/en/<LEVEL>/clips/`; mono AAC, 32 kbps, named by a hash of its recipe. What the app plays instead of synthesizing speech on the phone ([ADR 0008](adr/0008-bundled-pre-generated-speech-audio.md)). | Not the `audioTranscript` text itself, and not the `ttsSource` media specification (modelled, never spoken). |
| Audio manifest | A level's `assets/audio/en/<LEVEL>/manifest.json`: text key → speech role → clip, plus the bundle `contentVersion` it was generated for. Read by `AudioClipIndex`; held to the bundle by `level_audio_test.dart`. | Not part of the bundle JSON. |
| Text key | The first 16 hex digits of the SHA-1 of a spoken string after the shared normalisation (curly apostrophe to straight, whitespace collapsed, trimmed). The same in Dart (`textKeyFor`) and Python (`text_key`). | Keyed by the bundle text as authored, `{name}` slots included — never by what the engine was given. |
| Speech role | Whose voice a clip is in: `_` (the teacher voice, for vocabulary, grammar, key phrases, model texts and transcripts), a dialogue speaker label verbatim (`Maya`), a speaking task's `partnerSpeaker` label verbatim for its partner turns (`Anna`, `Waiter`), or `partner` — the generic voice for a speaking task that names nobody. The `speaker` argument of `TextToSpeechService.speak`. | Not a Skill, not a learner role. |
| Cast | `tool/audio/cast.json`: which engine voice reads the teacher role, the fallback partner role and each named label — dialogue speakers and `partnerSpeaker` values alike — plus voice pools by gender for labels it does not list. Global across levels, so a character sounds the same everywhere. | |
| Spoken answer | A speaking task's answer as the recogniser transcribed it. Graded by what was said, not how it was spelled: a word that sounds like one of the task's names counts as the name, common homophones are one word, digits are their words (`SpokenAnswer`, [ADR 0009](adr/0009-spoken-answers-graded-by-sound.md)). A typed answer, including the typed fallback of a speaking task, is graded as written. | Not a transcript shown to the learner — that is the review step before Check. |
| Model answer | A speak or write task's `accepted` list: what the feedback panel shows after a miss, the grader only for a task with no rubric, and what the Meaning signal compares the learner's answer with. Each one passes the task's own rubric, and every mastery task graded by a keyword checklist has at least one (both gates). | Not the rubric; not the only answer that passes. |
| Meaning signal | How close a free answer is in meaning to the task's model answers, 0 to 1, computed on the device by a small sentence-embedding model (`OnnxMeaningSignalService`, [ADR 0013](adr/0013-on-device-ai-for-free-answers.md)). Deterministic for a given model file. `null` when the task has no model answers or the model cannot run — then the rubric grades alone. | Not a grade: it adjusts the rubric's score by at most a quarter of the scale (see Grading signals), and is never used in the capstones or the placement test. |
| Grading signals | Everything known about a free answer when its grade is decided: the rubric's score (the base nothing replaces), the Meaning signal, a grammar penalty (from the AI pack, or LanguageTool for a learner without it) and the pack's verdict. One rule, `combineSignals`, moves the base by at most ±0.25 and clamps to 0..1; what was present is recorded in `activity_attempts.criteriaScores`. | Not `criteriaScores` as the capstones use it (per-criterion sub-scores); the two share the column, both JSON. |
| AI pack | A small language model a learner may download once from Settings ("Smart feedback") to judge free answers and explain them, entirely on the phone ([ADR 0013](adr/0013-on-device-ai-for-free-answers.md), Phase B — not built yet; the row says Coming soon). Its judgement is one of the Grading signals; its explanation is feedback only, shown with a "Generated on your phone" label. | Never required, never in the app binary, never consulted by the capstones or the placement test. |
