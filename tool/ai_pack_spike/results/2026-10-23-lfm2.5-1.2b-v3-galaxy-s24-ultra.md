# 2026-10-23 — LFM2.5 1.2B Instruct (Q4_K_M) on a Galaxy S24 Ultra, prompt v3, full CPU kernels

Spike build `f5f5396` (prompt v3: per-part booleans with the names fixed by the schema, mistakes as a list, verdict and count computed by code, English by script; Fast mode; `cpu_profile` back to full).

A second report pasted with it, labelled Qwen2.5 1.5B, is byte-for-byte the same judgements with the same load time (1537 ms) and the same memory numbers: the owner had selected and downloaded Qwen and pressed Run while LFM2.5 was still loaded, which the screen allowed and the report then mislabelled. Build v4 offers Run only for the loaded model and names the loaded model in the report. Qwen2.5 1.5B is therefore still untested.

## Reading

- **Speed — the kernel fix worked.** Median 18.3 s → **6.0 s**. Prompt evaluation 14.0 s → 2.6 s (~290 tokens, ~110 tokens/s, still re-read every answer: no prefix reuse for LFM2's hybrid architecture); generation 2.9 s → 3.3 s for more tokens (31 tokens/s, from 21); grammar sampling 0.9 s → 1.4 s for the larger schema (~14 ms a token). The email cases took 11.5 s because the model produced 190 tokens of "mistakes". On the 4 GB reference phone, two to three times slower is to be expected.
- **Memory:** 1693 MB after load, 1853 MB peak — 470 MB more than run 2 with the same file, presumably the full kernel set and its working buffers. To be watched on a 4 GB phone.
- **Judgement — first signs of reading, but near chance.** 13 of 22 verdicts right (the all-yes baseline is 11). Real negatives appeared: "Go away." not polite, "Hello! My name is Omar." incomplete, "Every weekend I go to the beach." not last weekend, the shirt not the shoes. But the model decided per *task*, not per answer: all five likes answers true (the weather too), all three routine answers true ("Yes." has three sentences), all four intro answers false (the complete one too), all four email answers true, both weekend answers false. Per-part output is a verdict on the task's shape, not a reading of the learner's text.
- **Mistakes and explanations copied the MODEL ANSWER.** "I don't like tennis" → "I don't like tennis." listed as the learner's mistake on the tea-and-milk answer; six "mistakes" on every email answer, all phrases from the model answer ("volunteers" → "volunteering", "Saturdays" → "Saturday"); explanations such as "The learner should say 'I don't like tennis' instead of 'I can't stand milk'". The model answer was the one piece of text in the prompt it could copy, and it did. Prompt v4 removes it.
- **Arabic:** not asked (Fast).

What this decides: three runs, three ways of asking, and no 1B-class model has read a learner's answer. Prompt v4 removes the last copy source and adds Qwen2.5 3B (2.1 GB, research licence, for the owner's 11 GB phone only) to find out whether the failure is size or approach. The alternative being weighed for Phase B is to drop the generative judge for small task-specific models: a natural-language-inference cross-encoder for "does the answer do part X" (deterministic, ~100 ms, tens of MB, through the ONNX runtime the app already ships) and a grammar-correction model for the mistakes, with the explanation templated from their output in both languages.
