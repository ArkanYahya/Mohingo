# تعليمات تسليم الحزمة إلى نموذج برمجي

استخدم النص التالي مع نموذج الذكاء الاصطناعي الذي سيعدّل البرنامج:

> ادمج حزمة `a1-modular-course` كمصدر محتوى A1 كامل. ابدأ بقراءة `manifest.json` و`README_AR.md`. للاستخدام وقت التشغيل حمّل `dist/a1-course-bundle.json`، ولا تدمج ملفات الوحدات يدوياً في ملف مصدر واحد. حافظ على جميع IDs كما هي، واربط التقدم بدليل `mastery` وCan‑Do لا بعدد الأسئلة. لا تجعل `practice` دليلاً على الإتقان. اعرض بديل الكتابة إذا تعذر الميكروفون، لكن لا تحتسبه Speaking. نفّذ أنواع الأنشطة المعرفة في `domain.json`. استخدم `mediaSpecifications` لتوليد/ربط الصوت؛ سجلات `ttsSource` تحتوي النص واللغة وملف الصوت الفعلي يمكن توليده أو تخزينه وفق بنية التطبيق. بعد الدمج شغّل أدوات التحقق والبناء، ولا تعتبر المهمة مكتملة إذا فشل أي فحص.

## ترتيب العمل المطلوب من النموذج

1. افحص نموذج البيانات الحالي في البرنامج وحدد طبقة adapter واحدة بينه وبين الحزمة.
2. حمّل الـbundle مرة واحدة وفهرس `units` و`grammar` و`lexicon` و`chunks` حسب `id`.
3. نفّذ renderer لكل قيمة في `domain.ACTIVITY_TYPES`.
4. خزّن evidence حسب `canDo + skill + mode`؛ لا تعتمد نتيجة كلية واحدة.
5. افصل شاشة التدريب عن `finalAssessment`، ولا تعرض مفاتيح الإجابة للواجهة.
6. اربط `finalMission` بعد إكمال U12.
7. أضف اختبارات تمنع IDs المكررة والمراجع المفقودة.
8. شغّل:

```bash
node tools/validate-a1.mjs
node tools/audit-quality.mjs
node tools/build-a1.mjs
```

## شرط القبول

يُقبل الدمج عندما تظهر نتيجة `valid` و`passed`، ويستطيع البرنامج فتح U0 وU12 والمهمة الختامية والاختبار، وتشغيل نشاط من كل نوع دون فقدان العربية أو النص الصوتي أو Can‑Do.
