# Conventions

Full rules: docs/CONVENTIONS.md. Key points worth not relearning:

- Files `snake_case.dart`; vars/functions `lowerCamelCase`; classes/widgets/providers `UpperCamelCase`; Drift columns match Dart field names exactly (no snake_case in payloads, to avoid a mapping layer).
- Feature-first layout: `lib/features/<feature>/{presentation,application,domain,data}`; shared/cross-feature code in `lib/core/`; local/remote data access in `lib/data/`. `lib/content/` (bundled curriculum) is a foundational layer *under* features — it never imports from `lib/features/`; grading logic for a bundle-defined `EvaluationSpec` lives in `lib/features/activity_engine/domain/evaluation/`, not in `lib/content/`.
- Typed exceptions thrown from the repository layer, caught and translated to user-facing copy only at the UI layer — never surface a raw exception message to the learner.
- TDD is the house style for this project — write the failing test first, watch it fail for the right reason, then implement minimally.
- Commits: short imperative summary line; no conventional-commits requirement; solo project, direct-to-main is fine for small changes. Only commit when the user explicitly asks.
- Every doc under docs/ has a "Last verified" line — bump it in the same change whenever that doc's subject matter changes; see CLAUDE.md's Definition-of-Done table for which doc maps to which kind of change (architecture/folder structure → ARCHITECTURE.md, DB/column → DATA_MODEL.md, colour/type/spacing → DESIGN_SYSTEM.md, copy/UX → UX_PRINCIPLES.md, test coverage → TESTING.md, etc.).

Testing pitfalls worth not rediscovering (full "what must be tested" list: docs/TESTING.md):
- A widget test that swaps `pumpWidget`'s `home:` between screens fully unmounts/remounts each time — it does NOT exercise the real production case of one screen `context.push()`-ing another on top while staying mounted underneath. A screen that seeds per-attempt/per-instance state in `initState()` and is keyed only by a stable slot id (not by the data it displays) will silently show stale data when reached via a real back-navigation, even though a pumpWidget-swap-based test passes. Fix/prevent by keying such widgets by something that changes with the underlying data (e.g. `ValueKey('$activityId-$attemptId')`), not just the slot id — and write at least one test using a real `GoRouter`/`Navigator` push+pop, not just `pumpWidget` swaps, for any screen that can be revisited this way.
- `ActivityAttempts.attemptedAt` (and similar timestamp columns) is stored at whole-second precision — a millisecond-precision "captured at" timestamp must be truncated to seconds before comparing against it, or a row written in the same wall-clock second as capture reads as stale/older than it is.
- Device-backed plugins (speech, connectivity, sound) need their Riverpod provider faked in any test that reaches them, or the test hangs/throws `MissingPluginException` — see docs/TESTING.md's "Platform services that must be faked" table. A fire-and-forget wrapper in the `playFeedbackSoundSafely` style (unawaited + catchError, matching `PendingRefinementDrainer.triggerDrain()`) is the one exception that's always safe to leave unmocked.
